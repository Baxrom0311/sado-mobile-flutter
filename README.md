# SADO Mobile (Flutter)

A premium speech-therapy companion for parents of 2–10-year-old children in
Uzbekistan. SADO is the consumer-facing front-end for the SADO platform — a
Duolingo-style experience that turns daily articulation, breathing and
phonemic-awareness practice into a game children actually enjoy.

> 🦜 **Mascot-driven UX** · 🎮 **Gamified XP / streaks / badges** · 🎙️ **On-device
> audio assessment** · 🌐 **Full Uzbek + Russian localisation** · 📡 **Offline-first
> with automatic resume**

---

## Highlights

- **30+ polished screens** — splash, 3-page onboarding, login/register,
  parent home, children list/detail/add/edit, exercise catalog with filters,
  assessment intro/game/results, progress dashboard with charts, badges,
  notifications, profile/edit-profile, settings, about, pending uploads.
- **Custom design system** — brand palette, Nunito typography (via
  `google_fonts`), 4 px spacing grid, soft colour-matched shadows, 16 / 12 /
  24-px radii, custom animated transitions on every route. No raw Material
  defaults leak through.
- **Parrot mascot** — `ParrotMascot` widget with idle / talking / happy / sad
  moods, custom-painted body, breathing animation, and `SpeechBubble`
  variant. Appears on home, exercise detail, assessment, results, empty
  states, error states.
- **Gamification** — XP, level curve, streaks, and 10+ unlockable badges
  persisted in Hive. Level-up and badge-unlock cascades trigger confetti +
  haptics + dialog cascade.
- **Audio pipeline** — `permission_handler` rationale flow, `record` 6.x
  AAC capture, live amplitude → custom `WaveformVisualizer`, in-app
  playback, 60 s cap with three-zone progress bar, queue-and-retry
  uploads via `PendingUploadsService`.
- **Offline-first** — `connectivity_plus` watcher, `OfflineBanner` auto-hides
  when online, paginated lists fall back to Hive snapshots, queued audio
  flushes the moment connectivity returns and surfaces a global snackbar.
- **Localisation** — `flutter_localizations` + ARB-driven L10n with full
  uz + ru parity (386 keys each). Zero hardcoded user-facing strings.
- **Testing** — 530+ unit and widget tests covering the gamification
  domain, API clients, navigation, every screen and most reusable widgets.

## Conventions & non-negotiables

- **No hardcoded user-facing strings.** Every label routes through `L.of(context)!` with matching uz + ru keys. CI guard: a Python parity check ensures `app_uz.arb` and `app_ru.arb` keep the same key set.
- **No default `CircularProgressIndicator`.** Custom replacements live in `widgets/loaders.dart` (`MascotLoader`, `BrandedSpinner`, `DotsLoader`) and `widgets/shimmer_loaders.dart` for skeleton screens.
- **No raw Material defaults.** Buttons go through `PremiumButton`, cards through `PremiumCard`, animations through helpers in `core/transitions.dart`.
- **Child model uses `name` (not `full_name`).** Only the `User` payload uses `full_name`. The mismatch is intentional — it mirrors the live API.
- **Lists are paginated.** Every list endpoint returns `{ "items": [...], "next_cursor": …, "has_more": bool }`; `paginated_exercises_provider` is the reference implementation.
- **Auth refresh handled in Dio.** `auth_interceptor.dart` retries on 401; if refresh fails it clears tokens and the router redirects to `/login`.
- **Offline fallback by default.** Repositories try the API first, then fall back to the Hive snapshot, never throwing back to the UI when cached data is available.

## Architecture notes

- **Riverpod scope** — `main.dart` boots Hive, opens `Preferences`, then
  installs `preferencesProvider` as an override on `ProviderScope` so the
  tree never sees an `AsyncValue` for prefs. Every screen consumes
  `authProvider`, `gameProvider`, and feature-scoped Riverpod providers.
- **Routing** — One top-level `redirect` decides splash → onboarding →
  login → app shell. Inside the shell, `ShellRoute` keeps the bottom nav
  alive across tab switches; the assessment FAB punches straight to
  `/exercises` with the child-picker bottom sheet.
- **Gamification** — `GameNotifier` writes XP / level / streak / badges
  to a single Hive box and exposes pure `recordAssessment` /
  `markActiveToday` methods. Pure functions in `gamification.dart` and
  `streak_calculator.dart` stay framework-free for unit testing.
- **Audio capture flow** — `assessment_game_screen.dart` orchestrates
  `permission_handler` → `AudioRecorderService` → live amplitude stream
  → `WaveformVisualizer`. On stop it either uploads via `AssessmentsApi`
  or, on failure, hands the recording to `PendingUploadsService` to be
  flushed automatically when connectivity returns.
